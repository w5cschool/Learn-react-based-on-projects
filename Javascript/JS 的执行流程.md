**结论先行（一句话版）：**
JavaScript 执行流程其实只有一条主线：

```
源码 → 词法分析 → 语法分析 → 字节码 → 优化为机器码 → 执行 → 垃圾回收
```



面试回答：

JavaScript 在执行时，先经过词法和语法分析生成语法树，然后被转换为字节码由解释器执行；引擎会将热点代码优化编译为机器码以提升性能。同时，JavaScript 是单线程，通过事件循环机制，将异步任务放入任务队列，在主线程空闲时依次执行，从而实现异步并发效果。



① 为什么 JS 有时会变慢？

因为代码结构变化导致优化失败，触发去优化（de-opt）。

② 为什么 Promise 比 setTimeout 先执行？

因为 Promise 属于微任务，会在当前宏任务结束后优先执行。

③ 如何写出高性能 JS？

保持对象结构稳定，避免频繁改变类型。



下面用 **5 分钟版本**帮你彻底理顺。

---

# 一、从你写代码开始发生什么？

你写：

```js
const a = 20;
```

浏览器不会直接执行这行代码，而是经历 6 个阶段。

---

## 第 1 步：Scanner（拆词）

引擎先把代码拆成最小单位：

```
const | a | = | 20
```

就像英语分词：

```
I love you
```

拆成：

```
I | love | you
```

这一阶段叫：

> ✅ 词法分析（tokenize）

---

## 第 2 步：Parser（生成语法树 AST）

引擎会理解代码结构：

```
这是一个变量声明
变量名 a
值是 20
```

生成一棵树（AST）：

```
VariableDeclaration
 └── a = 20
```

这一步是：

> ✅ 语法分析

---

## 第 3 步：预解析优化（Lazy Parsing）

关键优化：

### 未执行的函数不解析

```js
function foo(){}
function bar(){}

bar();
```

foo 不执行 → 不完整解析 → 提升加载速度。

---

## 第 4 步：Ignition（生成字节码）

代码变成：

```
人类语言 → 中间机器语言（字节码）
```

类似：

```
JS → JVM bytecode
```

此时可以执行，但还不是最快。

---

## 第 5 步：TurboFan（优化为机器码）

如果某段代码执行很多次：

```js
for(let i=0;i<100000;i++){
  add(1,2)
}
```

引擎会说：

> 这段代码经常用，优化它！

变成：

```
机器码（CPU直接执行）
```

速度暴涨 🚀

---

### ⚠️ 但优化可能失败（De-opt）

如果你这样写：

```js
foo({name:"a"})
foo({name:"a",age:1})
foo({name:"a",age:1,sex:1})
```

对象结构不断变：

TurboFan 无法优化 → 退回慢模式。

---

## 第 6 步：垃圾回收（GC）

运行过程中：

```js
let a = {x:1}
a = null
```

原对象没人引用：

```
→ 标记为垃圾
→ 回收内存
```

否则页面会：

* 越来越卡
* 内存爆炸

---

   ↓

# 三、面试 100% 会问的点

常见问题：

### Q1：JS 是解释型还是编译型？

答：

```
先解释执行，再 JIT 编译优化
```

---

### Q2：什么是 AST？

代码结构树。

---

### Q3：为什么 JS 有时慢？

因为：

* 未被优化
* 或触发 De-opt

---

### Q4：如何让 JS 更快？

关键：

```
对象结构保持一致
减少类型变化
减少嵌套函数
```

真正影响你项目性能的只有三点：

## ✅ 1. 不要频繁改变对象结构

React 状态尤其重要。

---

## ✅ 2. 热路径代码保持稳定

不要频繁改变参数类型。

---

## ✅ 3. 少写深层函数嵌套

减少重复解析。
